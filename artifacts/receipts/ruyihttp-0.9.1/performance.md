# RuyiHttp 0.9.1 性能回执

[成对基准作业](https://github.com/Facetomyself/ruyihttp/actions/runs/45670270866)在同一 ARM64 runner、同一单 CPU affinity 上，以 CPython 3.12.16 先后执行旧库 `ea44f8f` 和候选 `fae13b0`。轮询和 ABI 计数在计时之外；服务端为同机独立进程，每次都验证实际协议、内容哈希及热连接 ID。wheel 的 SHA 在原始数据 environment 中；基准作业独立构建，因此不假设与发行作业的 ZIP 字节相同。

| 工作负载 | 每版样本 | 耗时 p50（ms） | 客户端 CPU p50（ms） |
|---|---:|---:|---:|
| 热 H1 · 256 KiB | 18 | 12.17 → 1.78 | 11.72 → 1.44 |
| 热 H2 · 256 KiB | 18 | 10.69 → 3.50 | 9.80 → 2.75 |
| 热 H3 · 256 KiB | 18 | 14.92 → 14.88 | 7.46 → 7.12 |
| 新会话 H1 · 128 B | 24 | 8.96 → 4.84 | 7.47 → 3.57 |
| 新会话 H2 · 128 B | 24 | 53.73 → 55.48 | 11.17 → 6.39 |
| 新会话 H3 · 包含 Alt-Svc 引导 | 24 | 22.35 → 13.48 | 17.36 → 9.05 |

旧版与候选的默认 121 根证书信任材料构建 p50 分别为 **3.769 / 0.174 ms**。四个空闲 H2 连接每秒原生 pending 调用从 **397.5** 降至 **98.7**。大流未读时，源站可先发送的字节从 **12582912** 降为 **655360**，同连接 32 个小响应由 **0** 个完成增至 **32** 个，候选 p95 **1.67 ms**。1 MiB H3 上传的 JSON 正文帧字节 **1666754 → 0**，新版本用 ABI v1 实际交付全部有效字节；这是 Python/原生桥开销而非网络压缩。

高 RTT、大规模生产负载没有在这个对照中测量；H3 热下载耗时接近持平，冷 H2 即使 CPU 下降，墙钟中位数仍略升。不能把其他工作负载的收益外推到这里。
