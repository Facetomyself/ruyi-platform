# Clean D system-IME technical reconciliation — 2026-11-26 UTC

**Four genuine clean D field receipts on ARM64 and AMD64.** The missing receipt was a mechanical UI-driving issue. Direct clicks on the actual two fixed inputs and the separate Record button recovered it on both architectures. The recovered fourth receipt exposes a different product defect: focus moves during active preedit and the original field remains nonempty, despite zero stock GTK commit callbacks in the observed fourth round. Only the equal-text paste round passes the strict product checks. Physical display and human local IME remain **held on both architectures**.

## Diagnostic-only A/B: event type and trigger

[Wrapped GTK diagnostic](arm64-diagnostic-only-event-types.json) and [unwrapped distro GTK control](arm64-diagnostic-only-plain-gtk-event-types.json) used the same separately named diagnostic artifact and native Pinyin on ARM. This instrumented overlay adds bounded per-type counters to two fixed inputs with an inert visual scalar indicator. It retains the trust guard and existing round logic, does not submit new IPC or generate DOM events, and has a distinct bundle, app and fixture SHA-256. It is not clean D and its counters are not assigned to the sealed binary as exact clean-D event provenance.

- After `s h i` preedit, before the operation, all three IME rounds had **zero `compositionend`** of either trust class.
- Rank-2 key `2`, `Escape`, or pointer movement to the second input **each** caused exactly **one untrusted `compositionend` and zero trusted ends**, measured before any Record click. The select operation additionally produced one trusted `input` of noncomposing `insertText`; cancel and focus did not. Paste only produced the trusted paste and paste input. The active focus phase also recorded exactly one trusted secondary pointerdown and one trusted secondary focus.
- Every sampled diagnostic event-type count agreed with the normal distro GTK frontend without the stock-callback wrapper. The v2 wrapper is not required to reproduce this behavior. This isolates the operations to the native IBus Pinyin → stock GTK → Electron editing path, not the application's Record click or the observation wrapper; the internal Chromium call site remains unverified. The auditor should not assume a page-injected event merely from the v1 counter name `synthetic_events`.

## Handoff and production repair

Use the [operator and lab recipe](../../../acceptance/trace-linux-gap-closure-v1/product/desktop-seat/technical-qa/README.md) and [internal script-only kit](seat-technical-qa-kit-v1.tar.gz). On the future release candidate, a true native commit must emit a browser-authored trusted matching end and one composition-typed insertion; ESC must cancel composition; the native focus path must roll back only the active preedit range and fence late acknowledgements to the original focused-client generation. Preserve other committed field content, keep trusted-event and duplicate/stale checks intact, and retest both architectures with the same fixed fixture and controls. Do not treat an operator Escape-before-focus workaround as the active-focus challenge. Until the editing behavior is corrected, the operator should record and retain a failure instead of trying to obtain a green product result by changing the sequence.
