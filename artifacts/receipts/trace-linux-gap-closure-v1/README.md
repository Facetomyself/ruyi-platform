| `scoped-loopback-get-transaction` | 6 cases, 4 rows, 3 sealed zero windows | 6 cases, 4 rows, 3 sealed zero windows | Fetch: one network `GET`/`200` also observed by the loopback peer. Redirect: `302`→`200`, same native chain and two ordered peer paths. Cache: one native cache `GET`/`200`, one peer GET before arming, zero measured peer GETs. Skip, disabled, and foreign caller are sealed zeroes; the peer still observed the disabled and foreign-caller GETs. |

Wasm and JSCall rows are privileged SpiderMonkey Debugger boundary metadata, not JIT/opcode/instruction streams or Win74 parity. HTTP rows are Necko transaction metadata, not payload, packet or public all-origin capture. The foreign-caller HTTP test changes the calling document while contacting the **same** monitored endpoint, which is stronger than merely testing a different destination. These fixed cases are neither a broad validation of all request paths nor a proof that a future build retains any behavior.

**Candidate-002 WebSocket frame scope is `unsupported`, not a passing zero.** Separate smoke originals for both images record `complete:false`, `status:"unsupported"`, no arm receipt and `childSent:null`. The base kernels are unchanged by this overlay, and previous R5 WebSocket page/peer tests establish activity but do not establish native frame collection. WebSocket, IME, display and Electron remain separate unsigned cells, pending their own appropriate newer artifacts and review. There was no production site change in this review.

## Independent review and replay

From the platform checkout:

```sh
python3 -B artifacts/receipts/trace-linux-gap-closure-v1/verify_candidate_002.py
python3 -B -m unittest discover -s tests -p 'test_trace_linux_gap_v1.py' -v
```

The [verifier](verify_candidate_002.py) uses Python's standard library, never invokes the bundled QA code, and needs no Docker, network, unpublished checkout or remote host access. It rejoins exact archive proof, config ID/layer list, installed and committed source hashes, separate Runtime build/repeat files, exact QA tar and per-attempt image. It independently compares raw ready/armed/header/seal receipts, scope configuration, whole-output enumerations, sandboxed Firefox writer-process metadata and readback controls. Each counted zero must have a real armed window, a complete `ok` seal, every drop counter zero, exactly the expected row count, intact original newline, and drained child counters. HTTP has a parent producer; zero IPC counters there are expected even on positive HTTP cases. It compares the primary/foreign page and independent peer witnesses against the pinned case and prior workload; the packet's framed original, page and peer inputs must equal the original bytes, not a reserialization. All native row totals come from original JSONL; paired/zero counts, peer metrics and intake projections are derived summaries, not additional samples.

The ZIP establishes byte integrity from the fixed digest, not who could write the data at capture time. This review independently analyzes two retained native host lanes, rather than rerunning or remotely attesting their hosts. The capture runner's `/proc` observation, peer handler and whole-output scan are separate witnesses within the same per-run QA environment and share its trust boundary. The browser page acknowledgment is not an independent third-party human witness. `local_archive_rehashed:false` correctly states that the Docker archives remained with their native hosts; the compact bundle retains and validates the actual export/readback receipts. An external reviewer with retained archive files can additionally pass `--archive-arm64 /path/to/archive` and `--archive-amd64 /path/to/archive` to hash their actual bytes, and should independently obtain the pinned digests, review the chain of custody and authenticate the collection actors. The verifier's success and any rehash still leave formal external review and product signing open.
